# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览（发生率取自唯一有效重算版本）
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、重新打开和审计
- `/trends`：批号发生率与阈值核对（与总览、批次页同源）
- `/batches`：现场报告补录/撤回、批号装机量修正、并发冲突处理、批号物化结果
- `/audit`：信号审计与重算事件统一时间线、断点续算演练、失败恢复、审计包导出

## 可恢复重算模型

报告、批号装机量、发生率、任务期限和审计接入一次可恢复重算：

- **事实层**：现场报告以外部报告号为幂等键（重复补录只算一次，撤回保留审计行）；
  一份报告覆盖多个批号时按批号等分拆账。批号装机量带 `revision` 乐观锁。
- **物化层**：批号发生率快照只在重算任务 `finalize` 时整体升版本提交。
  报告一变化，受影响批号立即标记“待更新”并沿用上次完整数字；其余批号保持上次结果。
- **任务流水线**：`标记失效 → 批号发生率 → 信号聚合与任务期限 → 版本提交`，
  每阶段 checkpoint 落盘。调查任务期限按新发生率收紧（超阈值 0.75% → 5 个工作日、
  临界 2% → 2 个工作日，只提前不顺延），与信号聚合数字在同一版本提交。
- **可恢复**：任一阶段写入失败，任务停在断点，顶部横幅与审计页可“从断点继续”；
  提交已落盘但信号表未应用时按 `appliedAt` 对账补应用，保证幂等、不留半套数字。
- **并发**：两人同时修正同一批号装机量，后到者输入保留为冲突，可选择覆盖或放弃，
  不静默覆盖先到结果。
- **单一版本**：总览、台账、批次页、趋势页和详情页只读同一个 `effectiveVersion`
  的物化快照，版本戳随数据展示。

存储仍为浏览器 `localStorage`（信号表 `medical-safety-signals-v1`，
重算状态 `medical-safety-recalc-v1`）。审计页可武装一次阶段故障来演练断点续算。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建、检查与测试

```bash
npm run check
npm run build
npm run test:recalc   # 重算引擎行为测试（幂等/拆账/冲突/断点续算/版本一致性）
```

无后端服务，页面使用确定性模拟数据。信号登记等表单先经过 SvelteKit Form Action
与 Zod 校验再写入本地 store；报告补录/撤回与装机量修正表单在客户端经同一套
Zod schema 校验后进入重算引擎。
